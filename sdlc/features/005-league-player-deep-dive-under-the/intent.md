# Intent: AI Season Summary in the League Player Deep-Dive

**Owner:** @ly2xxx · **Status:** proposed (approving the review gate approves it)

## Problem
Players can see four metrics in the League Player Deep-Dive, but nothing turns those numbers into an explanation of how their season is actually going. They have to interpret averages, birdies and consistency themselves, which many casual players in the club cannot do. As a result the deep-dive answers "what are my numbers" but not "how was my season".

## Outcome
Directly under the four metrics in the League Player Deep-Dive view, there is a "🤖 AI 赛季总结" button. Pressing it produces a written season summary for the currently selected player, derived from that player's season rounds. The summary is generated by calling Ollama Cloud's chat API, with the API key and model name read from `st.secrets` the same way `auth.py` reads its secrets, and the summarization logic lives in a new `ai_summary.py` module. Automated tests exercise the flow with the outbound AI call mocked, so no credentials or network access are needed to run them.

## Done when
- The "🤖 AI 赛季总结" button is rendered in the League Player Deep-Dive view, below the four metrics.
- Pressing it shows a written season summary for the player currently selected in the deep-dive.
- The content sent for summarization is that player's own season rounds, not other players' data.
- API key and model come from `st.secrets`; no credentials are hard-coded and the app runs normally when the button is never pressed.
- Tests cover the button flow with the Ollama call mocked, and pass without credentials.
- The existing tests still pass.

## Not in scope
- Any change to the four existing metrics or how they are calculated.
- AI summaries anywhere else (Cup, Outing, Events, or a league-wide/whole-club summary).
- Persisting, caching or showing a history of previously generated summaries.
- Making the button admin-only or adding new admin/auth behaviour.
- Streaming output, retries, cost control or prompt-quality tuning beyond one usable summary.
- Changes to `auth.py` or to how secrets are otherwise managed.

## Open questions
- What exactly counts as "season rounds"? Assumption: all rounds for the selected player already loaded by the deep-dive view for the current season, with the same per-round fields the view already uses.
- Who may press the button? Assumption: any visitor who can see the deep-dive, since no admin gating was mentioned.
- What happens when secrets are missing or the API call fails? Assumption: the user sees a readable error in place of the summary and the rest of the page keeps working.
- What language and length is the summary? Assumption: Chinese prose, a few short paragraphs, given the Chinese button label.
- Is re-clicking expected to regenerate? Assumption: yes, one request per click, no caching.
